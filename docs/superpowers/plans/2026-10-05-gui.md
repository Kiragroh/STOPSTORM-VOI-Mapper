# Local GUI tester implementation plan

Approved design: local browser application, single-name lookup and case-aware CSV
batch review, STOPSTORM/TG-263 selection, ranked uncalibrated scores, observed
Ollama/model/GPU status, English documentation and synthetic screenshots.

Architecture: preserve the evaluated CLI/core. Add independent catalogue,
ranking, Ollama transport and loopback HTTP modules, with packaged static UI.
Use Python standard library at runtime; xlrd only for the optional official
TG-263 import. No cloud providers or automatic model downloads.

- [x] Import the official TG-263 worksheet with pinned SHA-256 and attribution;
      keep the downloaded catalogue outside the published repository.
- [x] Implement deterministic ranking, model shortlist reranking, strict response
      validation, review guards and per-case duplicate checks. Test unknown names,
      conflicting sides, numbered targets, duplicate rows and malformed outputs.
- [x] Implement loopback-only transport, coordinator job ownership, live status,
      bounded background jobs and cancellation. Test origin/Host protections,
      payload limits, failure states and exports.
- [x] Build the English responsive UI with single/batch modes, accessible status
      lights, candidate details, CSV import/export, progress and cancellation.
- [x] Test the unchanged CLI and new modules; exercise the GUI at desktop/mobile
      widths and run synthetic Qwen inference through the shared coordinator.
- [x] Package assets, capture actual synthetic-data screenshots, document setup,
      score semantics, privacy and hardware-status limitations.

Verification before publication: 39 Python tests passed; desktop (1360 px) and
mobile (390 px) browser checks passed. Explicit synthetic Qwen requests completed
through the shared coordinator for STOPSTORM and TG-263. A clean environment
installed the wheel and imported all 717 TG-263 entries. The CLI smoke test
reported zero duplicate master assignments. Original CLI core, prompt and
vocabulary are unchanged from the frozen study implementation.

Publication: commit the reviewed changes, fast-forward the existing main branch,
push to the established remote, and verify the remote tree and CI run. Do not
publish the downloaded worksheet, cache, environment or live-test result files.

Acceptance: no DICOM or manuscript changes, no duplicate accepted case/master
pairs, no claim of calibrated probabilities, no green GPU/model status without
an observed basis, no external request triggered by visiting the GUI.
